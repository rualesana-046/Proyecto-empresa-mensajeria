# 02 · Escenarios de calidad

> [NOMBRE 1], [NOMBRE 2], [NOMBRE 3] · [GRUPO 5A/5B]

Formato de seis partes. Las medidas "obtenidas" salen de ejecuciones reales de `npm run demo`, `npm run chaos` y `npm run escala` (ver README).

## E1 · D1 — Estado visible en menos de 3 s

| Parte         | Valor                                                                                                                                                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Mensajero                                                                                                                                                                                                               |
| **Estímulo**  | Reporta que el envío pasó a `RECOGIDO`, `EN_RUTA` o `ENTREGADO` (`POST /envios/:id/estado`)                                                                                                                             |
| **Artefacto** | envios → outbox → Redis Streams → notificaciones → canal SSE                                                                                                                                                            |
| **Entorno**   | Operación normal, un cliente con `EventSource` abierto, todos los servicios arriba                                                                                                                                      |
| **Respuesta** | El cliente recibe el evento empujado por SSE sin pedirlo                                                                                                                                                                |
| **Medida**    | Tiempo petición del mensajero → llegada al cliente **< 3.000 ms** en el 100 % de los cambios. **Obtenido:** 56–107 ms en 5 corridas seguidas (RECOGIDO 56–73 ms; EN_RUTA y ENTREGADO 102–107 ms); el máximo fue 107 ms. |

## E2 · D2 — Cobro exacto con la pasarela inestable

| Parte         | Valor                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Pasarela de pagos externa                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Estímulo**  | Responde 503 sin cobrar (30 % de las llamadas) o cobra y responde a los 3 s, después del timeout de 2 s (20 %)                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Artefacto** | Servicio cobros (trabajador de cobro) y su base `cobros_db`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Entorno**   | Ráfaga de 20 envíos contra entrega llevados a `ENTREGADO` en paralelo                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Respuesta** | Cobros reintenta con retroceso exponencial y la misma llave de idempotencia hasta confirmar cada cobro                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Medida**    | Cobros reales en la pasarela **= 20** (ni perdidos ni duplicados); 100 % `CONFIRMADO`. **Obtenido (5 corridas):** 20 reales en 5 de 5; 31–37 intentos; 5–10 cobros repetidos absorbidos por la llave; la ráfaga tardó entre 10,3 y 26,4 s (el resultado es aleatorio: la pasarela usa `Math.random`). Con `HONOR_IDEMPOTENCY=false` (3 corridas): **25–36 cobros reales para 20 envíos**, la verificación falla en 3 de 3. En modo determinista (`LOST_FIRST_REPLY=true`): con la llave siempre 20 (medido 20 reales y 20 repetidos ignorados); sin ella siempre ≥ 40 (medido 54). |

## E3 · D2 — Cobros caído durante la entrega

| Parte         | Valor                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Falla de infraestructura (contenedor detenido)                                                                                                                                                                                                                                                                                                                 |
| **Estímulo**  | El servicio cobros se detiene justo antes de que el envío llegue a `ENTREGADO` y vuelve después                                                                                                                                                                                                                                                                |
| **Artefacto** | Grupo de consumo `cobros` sobre `ev:envio.entregado`; tabla `cobros`                                                                                                                                                                                                                                                                                           |
| **Entorno**   | Cobros caído 5 s o más; el resto del sistema sigue atendiendo                                                                                                                                                                                                                                                                                                  |
| **Respuesta** | El evento espera en Redis; al volver, Cobros registra la intención y cobra una sola vez                                                                                                                                                                                                                                                                        |
| **Medida**    | 0 intentos de cobro mientras está caído; **exactamente 1** cobro real al volver. **Obtenido:** 0 intentos, `lag` del grupo = 1, 1 cobro real. Variante más dura (no automatizada en `chaos.mjs`, ejecutada a mano): `docker compose kill cobros` en plena ráfaga de 20 → 20 cobros reales para 20 envíos (repetido en 2 sesiones distintas, 35 y 38 intentos). |

## E4 · D3 — Asignación concurrente con réplicas

| Parte         | Valor                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Remitentes (muchos a la vez)                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Estímulo**  | 30 envíos creados simultáneamente en la misma zona (`norte`, 2 mensajeros de capacidad 20)                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Artefacto** | Servicio asignacion con 3 réplicas en el mismo grupo de consumo; tabla `mensajeros`                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Entorno**   | `docker compose up --scale asignacion=3`; volumen equivalente a un pico muy superior a 1.000 envíos/día                                                                                                                                                                                                                                                                                                                                                                                         |
| **Respuesta** | Cada envío se asigna una vez; las réplicas se reparten el trabajo sin pisarse                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Medida**    | 0 envíos con dos `envio.asignado`; 0 mensajeros con `carga > capacidad`; `carga` = asignaciones activas. **Obtenido (5 corridas en 3 sesiones):** 30/30 asignados en todas; 0 duplicados y 0 descuadres en todas; carga final 15 y 15 (≤ 20). El reparto entre réplicas cambia en cada corrida (p. ej. 15/13/2, 3/14/13, 6/18/6): las tres trabajan, pero no en partes iguales. **No** se probó un día de 1.000 envíos sostenidos: este escenario prueba concurrencia, que es lo difícil de D3. |

## E5 · Modificabilidad — Cambiar de pasarela

| Parte         | Valor                                                                                                                                                                                                                                                                                                                        |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Dirección financiera                                                                                                                                                                                                                                                                                                         |
| **Estímulo**  | Decide cambiar de proveedor de pagos                                                                                                                                                                                                                                                                                         |
| **Artefacto** | Código del servicio cobros                                                                                                                                                                                                                                                                                                   |
| **Entorno**   | Tiempo de desarrollo, sistema en producción                                                                                                                                                                                                                                                                                  |
| **Respuesta** | Se reemplaza el adaptador de la pasarela sin tocar los demás servicios ni el contrato de eventos                                                                                                                                                                                                                             |
| **Medida**    | Cambios limitados a **2 archivos** (`services/cobros/pasarela-cliente.js` y `services/cobros/config.js`); **0** archivos tocados en envios, asignacion, notificaciones y `shared/`. _Medida de diseño, no ejecutada:_ no se integró una segunda pasarela. Condición: que la nueva ofrezca llave de idempotencia (riesgo R3). |

## E6 · Disponibilidad — Notificaciones caído (complementario)

| Parte         | Valor                                                                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Fuente**    | Falla del servicio notificaciones                                                                                                         |
| **Estímulo**  | Se detiene notificaciones                                                                                                                 |
| **Artefacto** | Flujo envíos → asignación → cobros                                                                                                        |
| **Entorno**   | Operación normal con un envío contra entrega                                                                                              |
| **Respuesta** | El envío se asigna, se entrega y se cobra igual; al volver, Notificaciones procesa lo que se perdió                                       |
| **Medida**    | Envío `ENTREGADO` y cobro `CONFIRMADO` con Notificaciones caído. **Obtenido:** sí; al volver, el historial del envío tenía los 6 eventos. |
